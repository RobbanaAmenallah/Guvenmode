Display:
- Merchandise subtotal.
- Applied discounts.
- Delivery charge.
- Taxes if configured.
- Final payable total.

When confirming an order:

1. Validate customer inputs.
2. Validate product and variant status.
3. Validate current server-side prices.
4. Validate active promotion rules.
5. Validate delivery rules.
6. Validate available stock.
7. Create the order and order items atomically.
8. Reserve or deduct inventory according to the chosen policy.
9. Create a stock movement/audit record.
10. Save the payment method and initial payment status.
11. Generate a unique order reference.
12. Record the original financial amounts.
13. Commit the database transaction.
14. Show the confirmation only after successful commit.

Use a PostgreSQL transaction / Supabase RPC with suitable locking and consistent inventory updates to prevent overselling.

Ensure checkout requests are idempotent.

Do not create duplicate orders when the customer double-clicks or retries a request.

If stock becomes insufficient, return a meaningful French error and allow the customer to adjust the cart.

# 20. ROW LEVEL SECURITY AND SECURITY

Enable RLS on applicable exposed Supabase tables.

Security requirements:

- Public visitors can read only published catalog and approved public content.
- Customers can read and edit only their own profiles, addresses, carts, and wishlists.
- Customers can read only their own orders.
- Admin access must be role-verified.
- Public users must never edit inventory.
- Customers must never modify product prices.
- Customers must never arbitrarily modify order payment statuses.
- Customers must never directly update admin roles.
- Checkout writes must occur through trusted backend operations.
- All admin mutations must be protected server-side.
- Never trust a client-supplied user ID or role.
- Verify Supabase Auth JWTs on protected API routes.
- Use secure Supabase JWT verification with trusted issuer and signing keys.
- Apply rate limiting on authentication-related and sensitive operations.
- Validate all user inputs.
- Prevent SQL injection.
- Avoid XSS vulnerabilities.
- Configure CORS properly.
- Use secure headers.
- Never log passwords or secret tokens.
- Avoid leaking customer personal data through analytics or logs.
- Protect storage access using appropriate bucket policies.
- Use least-privilege permissions.

Provide an initial administrator setup procedure without hardcoding administrator credentials.

For service-role operations, keep credentials exclusively server-side.

Avoid dangerous SECURITY DEFINER functions unless absolutely necessary; if used, carefully constrain permissions and search_path.
